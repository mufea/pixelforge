# Architecture

PixelForge AI is a single TypeScript repository: a Next.js App Router web application plus a sibling BullMQ worker that shares domain libraries. It is not a monorepo and not a Vercel-only app. Long-running image jobs, Redis, PostgreSQL, and private object storage are first-class runtime dependencies.

## System boundaries

```
Browser
  │ HTTPS, session cookie
  ▼
Next.js (App Router)
  │  pages, server actions, route handlers
  │  never holds provider API keys in client bundles
  ├─ Better Auth  ── PostgreSQL (users, sessions)
  ├─ Domain services (credits, jobs, assets, billing)
  │     ├─ enqueue job metadata ── Redis / BullMQ
  │     └─ presign upload/download ── S3-compatible storage
  └─ Admin / health / webhooks
        │
        ▼
Worker process (Node.js)
  │  claim job → reserve already exists
  │  load assets from storage
  │  call provider adapter (timeout, normalize, metrics)
  │  write output asset, settle or release credits
  └─ persist job events
```

**Inside the boundary:** authentication, authorization, projects, assets, jobs, credits, subscriptions, admin configuration, image conversion via Sharp, provider adapters, webhook handlers.

**Outside the boundary:** OpenAI, Google Gemini, Fal AI, Stripe, Midtrans, SMTP/Resend, S3 providers, the user's browser.

The public REST API, if enabled later, must call the same domain services as the App Router. It must not contain a second credit or job implementation.

## Process model

| Process | Responsibility | Persistence |
| --- | --- | --- |
| Next.js | UI, auth, validation, credit reservation, job enqueue, presigned URLs, webhooks, polling | PostgreSQL, Redis, S3 |
| Worker | Execute AI and Sharp jobs, provider I/O, settlement, retries | PostgreSQL, Redis, S3 |
| PostgreSQL | Source of truth for users, money/credits, jobs, assets | Durable |
| Redis | Queues, rate limits, cache of job progress only | Ephemeral |
| Object storage | Private original and generated bytes | Durable |

Redis job payloads store identifiers and validated metadata only. Image bytes never go in Redis.

## Request flow — billable AI operation

1. Browser submits a Zod-validated form. It may send a prompt, asset IDs, and a model ID. It must not send user ID, role, price, or credit balance.
2. Server loads the session, confirms email verification where required, and loads the model from the registry.
3. Server checks the model is enabled and advertises the requested operation and parameters.
4. Server estimates credits from the admin pricing table (not from the client).
5. In a database transaction: lock the credit account, reject if available < estimate, insert an immutable reservation.
6. Insert `AIJob` (`queued`) and enqueue BullMQ with `{ jobId }` only.
7. Client polls `GET /api/jobs/:id` (ownership-scoped) or uses a future event channel.
8. Worker: mark `processing` if still `queued` (idempotent), load inputs from storage, call the adapter with a timeout.
9. On success: write output asset, settle reservation, mark `succeeded`.
10. On retryable failure: exponential backoff, do not settle, do not create a second reservation.
11. On terminal failure or allowed cancel: release unused reservation, mark `failed` or `cancelled`.

## UI architecture

- Next.js App Router, React, TypeScript `strict`.
- Tailwind CSS and shadcn/ui. Lucide icons. No second component library.
- React Hook Form + Zod on forms. TanStack Query for job polling and lists.
- Dark navy / blue creative workspace, light and dark themes, responsive layouts.
- Loading, empty, and error states on every data view.
- Studio tools are thin pages over `lib/ai` capabilities. Disabling a model in admin hides or disables it without frontend rewrites.

## Authentication and roles

Better Auth with the Prisma adapter:

- Email/password with verification and password reset.
- Google OAuth when `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET` are set; otherwise the Google button is hidden and documented as unconfigured.
- Sessions in PostgreSQL, HTTP-only secure cookies.
- Roles: `user` and `admin`. Role is stored server-side. Admin routes re-check role on every request.

Email in development: if Resend and SMTP are unset, verification URLs are written to structured logs, never silently skipped in production.

## Configuration

`lib/env.ts` parses process environment with Zod at process start. Missing provider keys disable that provider in the registry and surface a typed `PROVIDER_NOT_CONFIGURED` error. They never produce a fake successful image.

## Observability

- JSON logs via pino. Redact Authorization, cookies, secrets, signed URLs, and raw image payloads.
- Per-job and per-provider latency, attempt count, and normalized error code in `AIJob` / `AIJobEvent`.
- `GET /api/health` checks process liveness; a deeper `/api/health/ready` checks PostgreSQL, Redis, and a storage head request.
- Worker heartbeats in Redis so admin can detect a dead worker.

## Future expansion

Image modules stay behind operation interfaces (`generate`, `edit`, `removeBackground`, `upscale`, `removeObject`, `convert`). Video or other media would add new operations and tables, not fork the credit or job engines.
